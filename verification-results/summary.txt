CHANGES AND WHY
Registration validates names, emails, field types and password size before calling database or hashing functions.
Membership routes reject invalid UUIDs with HTTP 400 instead of database errors.
Business-service error handlers return HTTP 400 for malformed JSON and 413 for oversized bodies.
The member account page displays actual active, expired, scheduled or revoked membership state.
Peer commit and sync writes are serialized to protect the read-validate-write critical section.
Added repeatable live verification, controlled benchmark and real-HTTP recovery scripts.
Corrected setup and architecture documentation to match the implemented admin panel and blockchain.

LIMITATIONS AND OUTSTANDING DELIVERABLES
Single coordinator and trusted peers; no Raft leader election or Byzantine fault tolerance.
All containers share one laptop; PostgreSQL databases share one instance.
Full-chain retrieval and scans limit large-ledger throughput.
Loss of journal storage or conflicting/corrupt histories can require manual recovery.
RabbitMQ stop/start recovery was demonstrated; deletion or recreation of broker storage was not tested.
Malformed or conflicting events currently retry; there is no dead-letter processing workflow.
The source archive contains code and evidence, not database dumps, passwords or saved chain volumes.
Browser automation could not attach to this chat browser session. Earlier user demonstrations supply UI evidence; API tests and frontend build were verified.
